# Performance Reports Directory

This directory contains performance test reports generated by the Lighthouse-based testing system.

## Directory Structure

```text
performance/
├── .gitkeep                    # Keeps directory in version control
├── README.md                   # This file
├── dashboard.html              # Performance dashboard (if generated)
├── [scenario-name]/            # Reports for specific test scenarios
│   ├── .gitkeep               # Keeps scenario directory structure
│   ├── raw/                   # Raw Lighthouse JSON reports
│   ├── processed/             # Processed analysis files
│   ├── reports/               # Human-readable reports (HTML, MD, CSV)
│   ├── fixes/                 # Auto-fix reports and backups
│   └── backups/               # Backups created before auto-fixes
└── archived/                  # Older reports moved here for retention
```

## File Management

⚠️ **Important**: Performance report files are **excluded from version control** to prevent repository bloat.

### Automatic Cleanup

The performance testing system includes automatic cleanup features:

- **Retention Period**: Reports older than 30 days are automatically archived
- **Size Limits**: Large report collections are compressed and archived
- **Cleanup Script**: `npm run perf:cleanup` removes old reports

### Manual Cleanup

To manually clean up reports:

```bash
# Remove all reports older than 7 days
npm run perf:cleanup --days=7

# Remove all reports for a specific scenario
npm run perf:cleanup --scenario=quick-check

# Dry run to see what would be deleted
npm run perf:cleanup --dry-run

# Archive old reports instead of deleting
npm run perf:cleanup --archive
```

## Report Types

### Generated Files

1. **Raw Reports** (`raw/`)
   - Original Lighthouse JSON output
   - Complete audit data
   - Largest files (can be 100KB+ each)

2. **Processed Reports** (`processed/`)
   - Analyzed and summarized data
   - Performance trends and comparisons
   - Smaller, optimized JSON files

3. **Human-Readable Reports** (`reports/`)
   - HTML reports with charts and visualizations
   - Markdown summaries
   - CSV data exports

4. **Fix Reports** (`fixes/`)
   - Auto-fix execution reports
   - Before/after comparisons
   - Backup restoration instructions

### Retention Strategy

| Report Type | Retention | Action |
|-------------|-----------|---------|
| Raw reports | 7 days | Delete after processing |
| Processed reports | 30 days | Archive monthly |
| HTML reports | 90 days | Archive quarterly |
| Fix reports | 180 days | Keep for audit trail |

## Configuration

Performance report retention is configured in:

- `config/performance/default.json`
- Environment variables
- Command-line options

## Best Practices

1. **Regular Cleanup**: Run cleanup weekly to prevent disk space issues
2. **Archive Important Reports**: Save critical reports before cleanup
3. **Monitor Disk Usage**: Check report directory size regularly
4. **CI/CD Integration**: Configure automatic cleanup in deployment pipelines

## Troubleshooting

### Large Repository Size

If your repository becomes large due to performance reports:

```bash
# Check current size
du -sh reports/performance/

# Emergency cleanup (removes all reports)
npm run perf:cleanup --force

# Check what's ignored by git
git status --ignored reports/performance/
```

### Missing Reports

If reports are unexpectedly missing:

```bash
# Check cleanup logs
npm run perf:cleanup --log-level=verbose

# Restore from archive
npm run perf:restore --date=2024-01-15
```
