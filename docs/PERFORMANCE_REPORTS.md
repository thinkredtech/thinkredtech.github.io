# Performance Reports Management

## Overview

This document describes the automated management system for performance testing reports to prevent repository bloat while maintaining operational efficiency.

## Problem Statement

Performance testing generates frequent report files that can accumulate and significantly increase repository size over time, affecting clone performance and storage efficiency.

## Solution Architecture

### Git Ignore Configuration

Performance report files are excluded from version control using comprehensive ignore patterns:

```gitignore
# Performance reports (generated by lighthouse/performance testing)
reports/performance/*/raw/
reports/performance/*/processed/
reports/performance/*/reports/
reports/performance/*/fixes/
reports/performance/*/backups/
reports/performance/*.json
reports/performance/*.html
reports/performance/*.csv
```

### Directory Structure Preservation

Essential directory structure is maintained through `.gitkeep` files:

- `reports/performance/.gitkeep` - Preserves main directory
- `reports/performance/README.md` - Directory documentation
- `reports/performance/quick-check/.gitkeep` - Preserves scenario directories

### Automated Cleanup System

The cleanup system provides configurable retention management:

**Script**: `scripts/performance/performance-reports-cleanup.js`

**Features**:

- Configurable retention periods (default: 30 days)
- Archive functionality instead of deletion
- Scenario-specific cleanup capabilities
- Size-based cleanup triggers
- Dry-run mode for testing operations
- Detailed logging and reporting

### Integration Points

**Performance Orchestrator Integration**:

- Automatic cleanup before comprehensive audits
- Configurable through performance settings
- Non-blocking operation (main operations continue if cleanup fails)

**Task Runner Integration**:

```bash
npm run perf:cleanup
```

## Usage Examples

### Basic Cleanup Operations

```bash
# Clean reports older than 7 days
npm run perf:cleanup -- --days 7

# Archive instead of delete
npm run perf:cleanup -- --archive

# Clean specific scenario only
npm run perf:cleanup -- --scenario quick-check

# Test what would be cleaned (dry run)
npm run perf:cleanup -- --dry-run

# Force cleanup all files
npm run perf:cleanup -- --force
```

### Configuration Options

```bash
# Set maximum directory size (in MB)
npm run perf:cleanup -- --max-size 50

# Enable verbose logging
npm run perf:cleanup -- --log-level debug
```

## File Type Management

### Excluded from Version Control

- Raw lighthouse JSON reports (typically 100KB+ each)
- Processed analysis files
- HTML reports with charts and visualizations
- CSV data exports
- Auto-fix reports and backups
- Cleanup execution logs

### Included in Version Control

- Directory structure markers (`.gitkeep` files)
- Documentation and README files
- Configuration templates
- Essential metadata files

## Retention Policies

| File Type | Default Retention | Cleanup Action |
|-----------|------------------|----------------|
| Raw reports | 7 days | Auto-delete after processing |
| Processed analysis | 30 days | Archive monthly |
| HTML reports | 30 days | Archive or delete |
| Fix reports | 30 days | Retain for audit trail |
| Cleanup logs | 30 days | Auto-clean |

## Configuration Management

### Automatic Cleanup Settings

```javascript
reporting: {
  retention: 30,           // days
  autoCleanup: true,       // enable automatic cleanup
  maxDirectorySize: 100,   // MB
  archiveOldReports: true  // archive instead of delete
}
```

### Environment Variables

The system supports environment-based configuration for different deployment scenarios.

## Monitoring and Maintenance

### Automated Monitoring

- Size checks before major operations
- Automatic cleanup triggers based on thresholds
- Warning logs for manual review requirements

### Manual Monitoring

```bash
# Check current directory size
du -sh reports/performance/

# Review cleanup logs
cat reports/performance/cleanup-report-*.json

# Check git status for ignored files
git status --ignored reports/performance/
```

### Emergency Procedures

```bash
# Emergency cleanup (removes all reports)
npm run perf:cleanup -- --force

# Restore directory structure if corrupted
mkdir -p reports/performance/quick-check
touch reports/performance/.gitkeep
touch reports/performance/quick-check/.gitkeep
```
